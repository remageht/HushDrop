## [0.5.0] - 2026-10-26

### Added
- **At-rest encryption of hosted files (`--encrypt-storage`)**: completed uploads are wrapped into an AES-256-GCM streaming container. Wire format V2: 16-byte magic (`HUSHDROP_ENC_V2\n`) + per-file random 8-byte base nonce + `segLen`, then `[u32 plainLen][AES-256-GCM nonce=base||BE32(counter), aad=magic]` frames of up to 4 MiB plus an authenticated EOF frame — truncated containers fail closed, spoofed frame lengths and trailing junk are rejected. Downloads stream-decrypt with `Content-Length` = plaintext size, `Accept-Ranges` is not offered for encrypted files. SHA-256 metadata stays the plaintext hash (computed before encryption). Upload/Files responses expose `isEncrypted`.
- **Key-file management**: the master key is a 32-byte random file auto-generated at `data/atrest.key` with 0600 semantics on first run (Android: app-private `filesDir/hushdrop_host/atrest.key`); the path is logged under `[SECURITY]` without ever logging key bytes. A wrong-size key file is rejected instead of silently used. Without the key file the stored content cannot be recovered — this is documented as an explicit trade-off.
- **Android host parity**: `AtRest.kt` (pure `javax.crypto` AES/GCM, no extra dependencies) mirrors the same V2 wire format — compatibility is pinned by a JVM test that decrypts a vector generated by the Go implementation (`knownGoVectorDecrypts`). `TransferManager.withEncryption()` wires uploads, share-intent hosted files and the download path; unit tests cover round-trips, corruption subsets, key-file lifecycle and writer lifecycle.
- **Live smoke coverage**: encrypted upload → disk container (magic header, exact framing size, no plaintext leak) → plaintext download with identical SHA-256 → idempotent chunk replay that does not rewrite the container → restart reuses the same key file.

### Changed
- `crypto.EncryptStream/DecryptStream` now take a 32-byte key (V2 wire format); the obsolete passphrase/Argon2id V1 design (never wired in any release) has been removed. At-rest encryption is intentionally key-file based: zero UX, device-local trust.
- **Brand icons embedded everywhere**: deterministic `scripts/gen-icons.ps1` (GDI+ droplet) generates the brand master (1024px), ICO set (16–256), PWA icons/apple-touch/favicon, Tauri icon set (win/ios/android) and Android launcher mipmaps with background `#0B0F19`; `apply-android-custom.js` gains step 6 (mipmap deploy), `build.ps1` step 2b embeds the icon into Go Windows binaries via go-winres (UTF-8-no-BOM `winres.json` — the Go parser rejects a BOM); splash screen in `frontend/index.html` (reduced-motion aware).

## [0.4.0] - 2026-10-26

### Added
- **Direct P2P transfers (WebRTC)**: signaling over WebSocket implemented on the Go standard library (RFC 6455, zero dependencies) with room isolation, up to 8 peers per room and a 64 KB message cap; new "P2P" tab with rooms, drag-and-drop DataChannel transfer (strict LAN-only `iceServers: []`, 64 KB chunks with SCTP backpressure) and instant clipboard sync.
- **Upload resume**: deterministic per-file session id (name+size+lastModified), new `GET /api/transfer/status` endpoint (Go and Android host in parallel) reporting received chunks; the client skips already-uploaded chunks, retries failed chunks (3 attempts, exponential backoff) and offers a "Resume" button for failed/cancelled transfers.
- **At-rest encryption groundwork**: AES-256-GCM streams with Argon2id-derived keys (16-byte salt, 12-byte nonce) in `internal/crypto/atrest.go` plus tests; `--encrypt-storage` config flag added (wiring into finalization is a follow-up).
- **Folder upload**: zero-dependency STORE-method ZIP builder on the client (`frontend/src/utils/zip.ts`).

### Fixed
- **CSP is now served by the servers, not the Tauri config**: strict `Content-Security-Policy` header on the Go PWA and the HTTP cert/helper landing (including `wss:` for signaling) and on the Android host certificate landing; the boot-splash script moved from `index.html` into the JS bundle so `script-src 'self'` holds without `unsafe-inline` (verified: inline scripts are blocked, app renders clean).
- Chunk-upload protocol violations (out of range, uninitialized session, beyond declared size) now return `400 Bad Request` instead of `500`.
- iOS Safari PWA: safe-area insets (notch/Dynamic Island) handled via CSS env variables, deferred `URL.revokeObjectURL` so downloads are not aborted by WebKit.

### Changed
- Bumped unified project version to `0.4.0` (Android `versionCode 40`).

## [0.3.2] - 2026-10-05

### Security & Hardening
- **Android Host Service Isolation**: Declared `HostForegroundService` with `android:exported="false"`, enforcing strict internal UI/plugin control and preventing unauthorized intent invocation.
- **Permission Minimization**: Completely removed broad storage and media permissions (`READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_AUDIO`, `READ_EXTERNAL_STORAGE`). System share targets now stream directly via `ContentResolver` delegate `grant-uri-permission`.
- **Cleartext Boundary Restriction**: Introduced `networkSecurityConfig` restricting cleartext communication strictly to localhost loopback helper endpoints.
- **Log Privacy**: Eliminated 6-digit PIN and raw IP addresses from Android `Log.i` logcat output (IPs are masked, PIN is shown exclusively in user-facing notifications).
- **Distribution Data Isolation**: Build scripts (`scripts/build.ps1`) verify zero `.key`, `.pem`, `.crt`, `.log`, or `.env` files exist in release staging directories; `./data/` runtime directories are isolated.

### Fixed
- **Self-DoS & Throttling Fix**: Unmetered public endpoints (`GET /`, `/health`, `/api/pair/info`) so health checks and pairing discovery never consume rate-limit quotas on Go core and Android embedded servers.
- **Frontend Polling Guards**: `HostPage` and `ReceivePage` now strictly guard file listing polling behind `isAuthenticated()`, preventing unauthenticated clients from burning IP rate limits.
- **Android 8+ Service Lifecycle**: Handled `stopHost` via `startForegroundService` on Android O+ to prevent background `IllegalStateException`.
- **Zero Raw Fetch Calls**: Replaced raw `fetch()` calls in `HostPage` and `SendPage` with centralized `apiClient.listFiles()` and `apiClient.fetchLocalBlob()`.
- **Sharing Bridge Consolidation**: Unified system share target handling inside `mobile/src/share.ts` without inline duplication in `SendPage`.

### Changed
- Unified version bump to `v0.3.2` across Go core, Desktop Tauri (`0.3.2`), Android APK (`versionCode 32`, `versionName 0.3.2`), and Web PWA.

## [0.1.0] - 2026-10-03

### Added
- Initial alpha release of HushDrop.
- **Core Go Server**: TLS 1.3 self-signed ECDSA P-256 certificates with SHA-256 fingerprint verification.
- **Security & Pairing**: 6-digit numeric PIN pairing with 10-minute TTL and rate limiting (5 failed attempts = 5-minute lockout).

- **Resumable Downloads**: HTTP Range requests with `206 Partial Content`.
- **100% Portable**: Local-only `./data` storage with zero AppData/Registry modification and zero external cloud telemetry.
- **PWA Frontend**: React + Vite + TypeScript interface with centralized API client.
